## 管理スクリプトの使い方

管理者が信頼できるローカルモジュールを用意し、`repository` という名前でRepository実装をexportする。今回のフェイクテストは一時ディレクトリの架空membersだけを使う。暗黙に揮発性MemoryRepositoryへ書いて成功扱いにしないため、CLIではモジュールを必須とした。

```sh
node --experimental-transform-types scripts/member-link.ts /absolute/path/repository.ts link fake-firebase-uid fake-member-id
node --experimental-transform-types scripts/member-link.ts /absolute/path/repository.ts unlink fake-firebase-uid fake-member-id
```

引数はRepositoryモジュール、link/unlink、UID、メンバーID。トークン・秘密鍵は渡さない。既存のデモmemberにはデモUIDがあるため、新UIDへ変更する場合は旧UIDを明示してunlinkしてからlinkする。unlinkはuidだけを除去し、プロフィールやロールは削除しない。ブラウザ用管理APIやFirebaseユーザー作成は追加しない。

Repositoryの可視範囲内でUIDの一意性を検査する。#28のFirestoreRepositoryは単一orgの範囲なので、今回も単一org設定（FIRESTORE_ORG_ID）と組み合わせる。複数orgを扱う将来のUID一意性・検索インデックスの設計は別レビューが必要。現在は既存Repositoryポートのallを再利用し、UID検索専用の共有契約は追加しない。

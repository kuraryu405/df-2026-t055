## 起動と自動検証

既存のNode v24.22.1を使います。標準PATHにあるNode v26では、この基点の `--experimental-transform-types` が使えません。

```sh
TASK_NODE24="$HOME/.nvm/versions/node/v24.22.1/bin"
PATH="$TASK_NODE24:$PATH" npm run typecheck
PATH="$TASK_NODE24:$PATH" npm test
PATH="$TASK_NODE24:$PATH" npm run build
```

上記はこの結合版のディレクトリで実行します。依存をまだ入れていない環境では、既存lockに従って `npm ci --ignore-scripts` を先に実行します。全262件のテストが成功しています。実行環境によってローカルHTTP/WebSocketの待受許可が必要です。

起動する場合は、ビルド後に次を実行します。同じ4311番で既にサーバーが動いている場合は追加起動せず、既存の画面を開きます。

```sh
API_PORT=4311 \
WEB_ORIGIN=http://localhost:4311 \
MODEL_PROVIDER=fake \
REPOSITORY_BACKEND=memory \
STORAGE_BACKEND=local \
"$TASK_NODE24/node" --experimental-transform-types apps/api/src/server.ts
```

[ローカルの職員画面](http://localhost:4311/staff) から始めます。これはFake生成、架空プロフィール、メモリ内のDB、端末内の素材を使うデモです。サーバーを停止するとメモリ内の作業・承認・記録は失われます。Vertexや本番の認証・DBに接続したデモとは分けて扱います。

## 支援の操作

デモアカウントに「職員1」「職員2」を用意しています。選択はタブ単位に保持するため、別タブでそれぞれを選ぶと、再読込を挟んでも同じ所属の二職員の操作を確認できます。本人は「本人 Aさん」を使います。確認用の素材と承認版・割当の準備を担当者が済ませてから、次の順で確認します。

1. 本人が割当版で「はじめる」を押し、任意の工程で「手伝って」を押す。送信中と、保存後の担当待ちを区別する。
2. 職員1が「担当します」を押す。職員2の画面で担当決定が伝わり、担当者向けの開始・再開操作が出ないことを見る。
3. 職員1が「対応を始める」を押す。記録の3欄を開き、入力して「後で記録する」で閉じる。支援や再開を記録保存の条件にしない。
4. 本人の希望を確かめたうえで「対応を終えてつづける」、または「対応完了のみを記録」を選ぶ。前者では本人が同じ版・工程に戻り、後者では本人が「つづける」を選べる。
5. 職員の「対応完了・後から記録」から記録を開く。入力が残り、後入力・保存ができることを見る。
6. 本人が「やめる」を押す。手順と進行ボタンが直ちに閉じ、再読込や遅延通知で戻らないことを見る。職員の停止通知確認は停止解除を行わない。

保存競合では、最新の保存内容と入力中の文章を並べて表示します。確認後に「入力を残して、最新版を基に編集を続ける」を選び、保存内容を確かめて保存し直します。保存に失敗しても入力は残ります。
